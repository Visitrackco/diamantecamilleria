¿De dónde salen estos datos?

El backend registra automáticamente cada llamada que recibe (sin contar los archivos del front: js/css/imágenes).

KPIs generales

Llamadas totales
Cantidad de peticiones a la API en el rango seleccionado.
Tasa de error
% de esas llamadas que respondieron con un error (status 4xx u 5xx).
Caídas (5xx)
De esas llamadas con error, cuántas fueron por una falla interna del servidor (no del usuario).
Tiempo promedio
Milisegundos que tarda el backend en responder, medidos en el propio servidor desde que llega la petición hasta que envía la respuesta.
Memoria actual
Memoria RAM (RSS) que está usando el proceso del backend, promediada en el rango.

Métricas por hora

Llamadas por hora
Cantidad de peticiones agrupadas por hora (zona horaria Bogotá).
Memoria RSS por hora
Promedio de memoria RAM usada por el proceso en cada hora.
% CPU usado por hora
% de CPU que consume el proceso del backend, muestreado cada 5 segundos y promediado por hora. No es el "load average" de Linux (ese valor no existe en Windows), sino el uso real medido con process.cpuUsage().

Rankings

Servicios más llamados
Ranking de endpoints (método + ruta) con más peticiones en el rango.
Servicio más llamado por hora
Para cada hora, cuál endpoint concentró más tráfico.

Mantenimiento

Purgar logs
Borra permanentemente los registros de auditoría (todos, o solo los más antiguos a N días) para liberar espacio en la base de datos.
